## Context

El endpoint `GET /quotations` (módulo Quotations del backend NestJS + Prisma) necesita
5 query params ADITIVOS para soportar filtros avanzados multi-select del listado de
cotizaciones. Hoy el endpoint solo soporta: `page`, `limit`, `status` (único),
`customerId` (único UUID), `createdFrom`/`createdTo`. IMPORTANTE: el frontend ya envía
un param `search` hoy y el backend lo ignora silenciosamente (no existe en el DTO) —
este cambio lo hace real.

Repo: `houndfe-backend`. Rama sugerida: `feature/quotations-list-advanced-filters`.
Stack: NestJS + Prisma + class-validator. Tests: jest (`pnpm test:unit`).

## Nuevos query params (contrato exacto)

### 1. `search` — string opcional
- Filtra por nombre de cliente: `firstName` OR `lastName`, `contains`, case-insensitive
  (Prisma `mode: 'insensitive'`).
- Trim del valor; vacío/ausente = sin filtro.
- Solo nombre de cliente (no id, no folio, no items).

### 2. `status` — MULTI (CSV), reemplaza el comportamiento single actual
- Acepta lista separada por comas: `?status=DRAFT,SENT` → OR entre valores.
- Valores válidos: el enum `QuotationStatus` del módulo (DRAFT, SENT, EXPIRED,
  CANCELLED — verificar literales exactos en el dominio). Valor inválido → 400 con
  mensaje claro.
- Vacío/ausente = sin filtro.
- BACKWARD COMPAT: el uso actual con un solo valor (`?status=DRAFT`) debe seguir
  funcionando idéntico.

### 3. `customerId` — MULTI (CSV), reemplaza el comportamiento single actual
- Acepta lista separada por comas: `?customerId=<uuid1>,<uuid2>` → OR entre UUIDs.
- Cada valor debe ser UUID válido; inválido → 400.
- Vacío/ausente = sin filtro.
- BACKWARD COMPAT: un solo UUID sigue funcionando.

### 4. `expiresFrom` / `expiresTo` — ISO 8601 date, opcionales
- Rango inclusivo sobre el campo `expiresAt`.
- `expiresFrom` solo = `>=`; `expiresTo` solo = `<=`; ambos = `BETWEEN`.
- Fecha inválida → 400.
- Backend decide el manejo de nulos (`expiresAt` puede ser null en drafts — documentar
  si el filtro excluye o ignora nulos; recomendado: nulos NO matchean un rango).

### 5. `minTotalCents` / `maxTotalCents` — enteros no negativos, opcionales
- Rango inclusivo sobre el total de la cotización (`totalCents`).
- `min` solo = `>=`; `max` solo = `<=`; ambos = `BETWEEN`.
- Validación: `min <= max` (si ambos presentes) → violación = 400.
- CUIDADO con falsy: `minTotalCents=0` es válido — usar checks de `undefined`/`null`,
  no `if (min || max)`.

## Semántica de composición

- **OR dentro de cada grupo** (multi-values de un mismo param).
- **AND entre grupos distintos** (search AND status AND customerId AND expires AND
  total AND created AND page/limit).
- Combinación completa debe ser estable con la paginación (`page`/`limit`).
