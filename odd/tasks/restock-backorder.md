# Restock backorder (pedido por reposición) — POS staff side

Contract v1 agreed between owner, chatbot and backend (backend `docs/proposals/restock-backorder-contract.md` §1, §3, §4, §6.5, §9; final in `docs/chatbot-handoff/`). This document covers the POS part (contract §9): a POS view to see and cancel backorders, reserved stock on product and POS search, the counter-sale reservation error, and staff notifications. Built against the contract first; not closed until checked against the real backend (:3003).

## Specs
- S1 Owner: «Vista propia en POS (Recomendado)» — «Nueva entrada «Pedidos por reposición» en el menú POS con pestañas por estado (En espera, Apartados, Confirmados, Vencidos, Cancelados), badge con apartados, y enlace a la solicitud del chatbot. Es una fila de espera de mostrador, no una conversación.»
- S2 Contract §9: «CASL subject **`Backorder`**: `read`, `update` (cancel). Grants seeded for Manager (read+update) and Cashier (read). No staff creation in v1.»
- S3 Contract §9.1: «Query: `page`, `limit`, `status` (comma list), `productId`, `variantId`, `customerId`, `q` (customer name/phone or product/variant name), `from`/`to` (`scheduledAt`, ISO with zone), `sortBy = scheduledAt|status|reservedUntil` (default `scheduledAt`), `sortOrder` (default `asc`). Branch from the token. Response: `{ items: BackorderStaff[], page, limit, total, counts: {WAITING, RESERVED, CONFIRMED, EXPIRED, CANCELLED} }` — `counts` honour every filter except `status`. `BackorderStaff` = `BackorderBot` plus `version`, `customer {id, name, phone}`, `origin: "CHATBOT"`, `chatbotRequestId`, `productImageUrl`, `priceListId`, `confirmedAt`, `cancelledAt`, `expiredAt`, `cancelledBy {id, name} | null`, `saleStatus | null`, `etaOverdue`, `passedOverCount` (POS flag for a head that keeps being passed over, Q1).»
  BackorderBot (§6.5): `{ "id": "uuid", "folio": "BO-000012", "status": "RESERVED", "productId": "uuid", "productName": "Croquetas Adulto Raza Grande 18 kg", "variantId": null, "variantName": null, "quantity": 2, "referencePriceCents": 114900, "currentPriceCents": 109900, "finalPriceCents": 109900, "scheduledAt": "…", "estimatedAt": "…", "estimatedArrivalDays": 7, "reservedAt": "…", "reservedUntil": "…", "reminderAt": "…", "queuePosition": null, "saleId": null, "cancelledByKind": null, "cancelReason": null, "branchName": "Centro", "customerFirstName": "Rosa" }` — «`queuePosition` (1-based) only while `WAITING`. All timestamps ISO 8601 with offset (e.g. 2026-11-21T12:05:00-06:00).»
- S4 Contract §1 states: «WAITING ──(stock arrives, FIFO head, full qty available)──▶ RESERVED / RESERVED ──(bot checkout with backorderId)──▶ CONFIRMED (terminal; saleId set) / RESERVED ──(24 h without checkout)──▶ EXPIRED (terminal; units go to the next WAITING, else general stock) / RESERVED ──(reserved lot expired, no valid lot to swap)──▶ WAITING (keeps scheduledAt = front of the queue; feed backorder.reservation_lost) / WAITING | RESERVED ──(customer or staff cancel)──▶ CANCELLED (terminal; RESERVED units go to the next)»
- S5 Contract §9.2–9.3: «`GET /backorders/:id` → `BackorderStaff`; `404 BACKORDER_NOT_FOUND`.» «`POST /backorders/:id/cancel` `{ reason?: ≤280, version }` → `BackorderStaff`. Errors: `409 BACKORDER_NOT_CANCELLABLE {status}`, `409 VERSION_CONFLICT {currentVersion}`, `404 BACKORDER_NOT_FOUND`. RESERVED units go to the next backorder; the bot gets `backorder.cancelled_by_staff {reason}`.» Cancel only with `update:Backorder`, only for WAITING/RESERVED.
- S6 Owner: «Producto + buscador del POS (Recomendado)» — «En la lista/detalle de producto y en el buscador del POS: «Disponible 3 · Apartado 2». Al cobrar, si choca con lo apartado, mensaje claro al cajero.» Contract §9.4: «Product and variant reads used by the POS (products list/detail, POS catalog search) gain `stockOnHand`, `reservedForBackorders`, `availableToSell` (= today's `quantity`). Existing fields keep their meaning.» §3: «`stockOnHand = quantity + reservedForBackorders`; `availableToSell = quantity`.» Fields optional until the backend serves them; nothing changes when absent or reserved = 0.
- S7 Contract §4: «Reservations are enforced at sale confirm (POS add-item stays advisory, `sales.service.ts:1347`). When confirm fails `STOCK_INSUFFICIENT_AT_CONFIRM` and `quantity + reservedForBackorders ≥ requested`, the error becomes **`409 STOCK_RESERVED_FOR_BACKORDER {available, reserved}`**. POS add-item can show the same code as a warning.» The cashier message must not read as «sin stock».
- S8 Contract §9.5: «When a backorder becomes `RESERVED` or `EXPIRED`, a staff notice with `backorderId` through the existing notifications module (same channel as chatbot request notices).» §4/§10: «If the bot reports that `backorder.reserved` or `backorder.reservation_reminder` could not be delivered (outcome `PROVIDER_REJECTED`), the staff get a notice with `backorderId` so they call the customer.» Notification links open the backorder.
- S10 Backend L11: «DELETE /customers/:id responde 409 CUSTOMER_HAS_ACTIVE_BACKORDERS cuando el cliente tiene un backorder en espera o apartado, con body {statusCode, error, message, timestamp}». Deleting such a customer shows a clear message instead of a generic error; the customer stays.
- S11 Handoff 26 (odd/handoff/26-restock-backorder.md, «Stock fields, counter error and variant block»): stock fields at product root (GET /products, GET /products/:id + variants[i], GET /products/:id/variants) and inside `stock` in GET /sales/pos-catalog(/:productId); add-item/PATCH line `stockWarning = { code: "STOCK_RESERVED_FOR_BACKORDER", available, reserved }` (200, only that response); `POST /sales/drafts/:id/charge` 409 `{ error: "STOCK_RESERVED_FOR_BACKORDER", available, reserved }` (sale stays DRAFT); variant conversion (`POST /products/:id/variants`, `PATCH /products/:id` hasVariants:true) 409 `PRODUCT_HAS_ACTIVE_BACKORDERS` «El producto tiene pedidos por reposición activos», nothing changes.
- S12 Handoff 26 §4, §7: «503 … BACKORDER_RETRY_REQUIRED … Nothing was changed: retry the same request once.»; the cancel reason «is sent to the customer's bot (`backorder.cancelled_by_staff`), so the bot may quote it: ask for a customer-safe reason.»; `customer.phone` is the full international number, not masked.
- S9 Owner: «Ya, con tipos y tests (Recomendado)» — «Diseño la vista, tipos, API y pantallas con tests contra el contrato; no lo cierro hasta probarlo contra el backend real.»
