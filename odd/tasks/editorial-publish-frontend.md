S2. BE contract (e31af08e, verbatim): «POST /products/:id/editorial/draft/publish y POST /products/:id/editorial/draft/discard. Body cerrado {expectedCycle, expectedRevision}, Idempotency-Key obligatorio, los dos responden 200 con el EditorialState de siempre.» «Publish: copia el draft a Published con published.revision = anterior + 1 (1 si no había nada publicado), deja draft: null y mantiene el cycle.» «Discard: deja draft: null y no toca Published. NO valida el documento, porque es la salida para un draft que ya no se puede guardar ni publicar.» «Después de publish o discard, el próximo initialize va con expectedCycle = cycle actual, igual que hoy.» BE b1c0466e: «initialize siempre crea el draft con cycle = anterior + 1 y revision 1 … una pestaña vieja con (N, r) recibe 409 en save, publish y discard.» Responses are the top-level EditorialState (optional `warnings` as with save); reuse the existing unwrap.
S3. Publish validation (e31af08e/b1c0466e/ceb5454a, verbatim): «Antes de publicar revalida el draft contra el contexto actual con las reglas y límites de un save fresco; si es inválido da 400 MALFORMED y no cambia nada. Una opción archivada solo pasa si la asignación idéntica ya está en el Published actual.» «Un archivado que se conservó en el draft pero no está en el Published actual se puede GUARDAR y NO se puede PUBLICAR.» «publish da 400 MALFORMED si commercialTitle es null o si commercialTitle.trim() === ''. … Se rechazan null, "" y "   ". El documento se publica tal cual está guardado, sin recortar.» (Title rule is an INTERIM minimum until real vocabulary families with D14 minimums exist.) «hasta que exista el slice de medios, publish rechaza mediaRefs no vacíos con 400 MALFORMED. Published no lleva medios en esta fase.» The FE prevalidates the SAVED draft with these rules before offering publish and explains each blocker; the server stays authoritative.
S4. Errors (e31af08e/b1c0466e, verbatim): «400 MALFORMED, 401, 403, 404 si el producto no está en el tenant, 409 CONFLICT si no hay draft activo, si el CAS está viejo o si se reusa la key con otro body. El replay con misma key y mismo body devuelve 200 con el resultado registrado y nunca republica.» «el envelope es exactamente {statusCode, error}, sin campos extra.» Correction (implementation, BE b016fe0a, verbatim): «Para publish y discard queda igual que en save: un producto inexistente o de otro tenant da 403 FORBIDDEN, así no se puede deducir si existe un producto de otro tenant, y 404 solo aparece si el producto desaparece después de autorizar.» Same intent rules as save (editor S9): new confirmed action → new key; ambiguous retransmission → identical key/body; receipt is historical, not current state; 409 → explicit reconciliation, never auto-resend; failures preserve local buffer and both versions.
S5. Permissions (e31af08e/b1c0466e, verbatim): «publish requiere el nuevo ProductEditorialDraft:publish + read; discard requiere read + update.» «El código que recibe el FE es exactamente 'publish:ProductEditorialDraft' … Un editor sin publish puede guardar y no puede publicar.» Feature-local exact checks only; no CASL/wildcard/manage substitution; grants stay MANUAL.
S6. Scope (e31af08e): «El usuario confirmó que el único consumidor de Published es el catálogo público; el POS no cambia. Va por slices: (1) publish/discard como transiciones de estado, (2) el catálogo público lee Published (C3.3), (3) medios.» This feature is slice (1) only: no public-catalog reads, media upload/removal, or POS changes.
S7. D13 UI (docs/redesign/product-vocabularies.md §7 item 8, verbatim): «distinguir publicado/no publicado, borrador guardado y cambios locales sin guardar; avisar al salir. Crear/retomar el único borrador, guardar, preview/diff autenticados `no-store`, publicar y descartar con confirmación. CAS de revisiones protege guardar/publicar/descartar; descarte obsoleto no elimina borrador nuevo ni publicado. Fallo conserva ambas versiones y entradas locales para corregir/conflicto, sin despublicación silenciosa.» Preview/diff is derived client-side from the authenticated GET state (draft vs published); no new endpoint. Publish acts on the SAVED draft revision only, so it is unavailable while local unsaved changes exist (save or discard local changes first).
S8. Media consequence (FE→BE, accepted in ceb5454a): a saved draft with non-empty `mediaRefs` cannot be published and this editor cannot remove media; the UI explains this before any attempt and offers discard with confirmation as the only exit.
S9. Integration limits: mocks only for this closed contract; no BE/DB/API mutations by FE; the real roundtrip happens only when BE asks after its implementation. Work units ~400 authored lines with tests and docs; independent verification for named security/async risks.
